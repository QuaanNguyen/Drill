# Drill maintenance

Keep the core independent of application repositories and their data.
Project-specific evaluation rules belong in adapters and their saved assets.
An ACCEPTED decision does not authorize publication or establish model qualification.

Use Drill's workspace command for research workers.
For tool maintenance, use .worktrees/maintenance/<task>/<worker> inside this repository.
Choose stable task and worker names.
Preserve existing branches and edits.
Do not create worktrees beside the repository.

Run python3 tools/verify.py with an output path before handing back a change.
Run the focused blast-radius proof when changing campaign selection or command routing.
Keep verification claims tied to executed checks.
Record unresolved concerns in GitHub issues with a reproduction and a completion check.

Do not add source comments or docstrings.
Do not manually edit generated campaign files or historical evaluation evidence.
Put each full sentence on its own line in long Markdown prose.
